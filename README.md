## 📌 Executive Summary

The **Neelkanth Protocol** is not an application – it is a **governance operating system**. It replaces institutional trust with **verifiable, deterministic logic**. Built on the **#MehendiPrinciple**, **#LongewalaDoctrine**, and **#GumnamKuheliPrinciple**, this pilot edition transforms compliance from reactive reporting into **autonomous Governance‑as‑Code**.

| Locked Baseline | Value |
| :--- | :--- |
| **Total FTEs** | 713 (611 operational, 102 governance, 143 reserve) |
| **Lines of Business** | 31 |
| **Governance Ratio** | 1:6 |
| **Audit Completeness** | 99.5% (target 99.9%) |
| **Logic Drift Threshold** | <1.5% |
| **Regulatory Breaches** | 0 |
| **Cumulative Value Protected** | ₹269.6 Cr (simulation + baseline) |

**The protocol does not ask for trust – it provides verifiable evidence.**  
Every decision carries an immutable `Trace‑ID`, every high‑risk action requires a `HAT‑ID`, and every control leaves an audit trail that can be reconstructed in under 6 minutes.

## 🛡️ Kill‑Switch & Reserve Activation (The “Teeth” of the Protocol)

### Kill‑Switch Triggers (Automatic)

| Condition | Threshold | Action |
| :--- | :--- | :--- |
| Queue depth | >50 for 2 consecutive cycles (10 min) | Pause intake; notify TIGER |
| Logic drift | >2.0% | Pause LOB; escalate to TIGER |
| Audit completeness | <95% for 2 consecutive hours | Freeze all new transactions |
| Trace‑ID coverage | <99% for any LOB over 1 hour | Pause that LOB |
| HAT compliance | <100% for high‑risk decisions (rolling 24h) | Block further high‑risk actions |

> *“Kill‑switch not triggered” is **not** a failure – it is governance discipline.*  
> Full specification: [`/docs/kill-switch-specification.md`](docs/kill-switch-specification.md)

### Reserve Activation Triggers

| Trigger | Reserve Deployed |
| :--- | :--- |
| Queue depth >50 for 5 minutes | 10 general reserve FTEs |
| Unplanned FTE absence (>20% of critical LOB) | Match headcount from general reserve |
| Kill‑switch activation | QRT + 20 general reserve; ERT on standby |
| Logic drift >1.5% and rising | QRT only |

Full specification: [`/docs/reserve-activation-specification.md`](docs/reserve-activation-specification.md)

## 🌑 Shadow Sentinel – Failover Governance Layer

**Grade A+ (DELTA certified)** – deterministic, AI‑free fallback that activates when primary Sentinel fails.

- **Triggers:** Primary Sentinel heartbeat loss >30s, audit completeness <95% for 2 cycles, TIGER manual override.
- **Capabilities:** Mirrors drift detection, HAT attestation, Trace‑ID generation using hardcoded thresholds.
- **HAT‑ID range:** `HAT-SHADOW-001…` (audit‑distinguishable).
- **Proven:** Correctly fired in **Scenario 2** (Workforce Governance Failure).

Read the specification: [`/docs/shadow-sentinel-spec.md`](docs/shadow-sentinel-spec.md)
